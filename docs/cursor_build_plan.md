# tea_assistant — Cursor Build Plan

## Цель
Собрать быстрый внутренний web app для сотрудников:
- поиск по артикулу и названию;
- фильтрация по параметрам;
- карточка чая;
- рекомендации на основе матрицы;
- AI-ввод через DeepSeek только как слой для свободного текстового запроса.

Стек:
- React
- Vite
- JSON-база
- логика на локальных данных
- деплой по ссылке

---

## Общие правила работы с Cursor Agent
1. Работать поэтапно, не просить сделать весь проект одной задачей.
2. После каждого шага проверять, что приложение запускается.
3. Сначала реализовать рабочий MVP без AI.
4. AI подключать только после того, как готовы поиск, фильтры и базовая логика рекомендаций.
5. Не добавлять backend, базу данных, авторизацию и лишние зависимости без отдельной задачи.
6. Интерфейс должен быть адаптирован под телефон.
7. Код должен быть простым, чистым и расширяемым.

---

## Этап 1. Инициализация проекта
### Задача
Создать новый проект на React + Vite.

### Что должно быть сделано
- создан базовый проект;
- удален лишний шаблонный код;
- настроена чистая структура папок;
- подключен общий файл стилей;
- приложение успешно запускается локально.

### Результат этапа
Есть пустой, но рабочий каркас проекта `tea_assistant`.

---

## Этап 2. Подготовка структуры файлов
### Задача
Создать базовую файловую структуру проекта.

### Что должно быть создано
- `src/components/`
- `src/services/`
- `src/utils/`
- `src/data/`
- `public/teas.json`
- `src/App.jsx`
- `src/styles.css`

### Результат этапа
Проект соответствует утвержденной архитектуре.

---

## Этап 3. Подключение данных из JSON
### Задача
Подключить `public/teas.json` и загрузить данные в приложение.

### Что должно быть реализовано
- сервис загрузки списка чаев;
- чтение JSON через `fetch`;
- хранение списка чаев в состоянии приложения;
- базовая проверка, что данные отображаются.

### Результат этапа
Приложение умеет читать вашу базу чаев из JSON.

---

## Этап 4. Поиск по артикулу и названию
### Задача
Сделать быстрый поиск.

### Что должно быть реализовано
- поле ввода;
- поиск по `article`;
- поиск по `name`;
- частичное совпадение;
- обновление списка результатов в реальном времени.

### Результат этапа
Сотрудник может быстро найти нужный чай по артикулу или названию.

---

## Этап 5. Список чаев и карточка результата
### Задача
Сделать отображение списка и карточки выбранного чая.

### Что должно быть реализовано
- список карточек чаев;
- краткий вид карточки;
- выбор карточки;
- детальный блок с полной информацией о чае.

### В карточке должны отображаться
- название;
- артикул;
- тип;
- описание;
- вкус;
- аромат;
- эффект;
- способы заваривания;
- рекомендации по завариванию;
- подходит ли новичку;
- альтернативы.

### Результат этапа
Есть рабочий просмотр базы чаев.

---

## Этап 6. Фильтры
### Задача
Сделать ручную фильтрацию по основным параметрам.

### Минимальный набор фильтров
- тип чая;
- ключевые теги;
- антитеги / исключения;
- новичок;
- термос;
- пролив;
- время употребления.

### Что должно быть реализовано
- панель фильтров;
- множественный выбор значений;
- сброс фильтров;
- комбинирование поиска и фильтров.

### Результат этапа
Сотрудник может вручную сузить выборку по запросу клиента.

---

## Этап 7. Логика рекомендаций
### Задача
Добавить ранжирование результатов по вашей матрице и правилам.

### Что должно быть реализовано
- функция scoring;
- учет тегов;
- учет антитегов;
- учет новичка;
- учет способа заваривания;
- учет жестких исключений;
- сортировка результатов по score.

### Что должно быть показано пользователю
- основной вариант;
- 1–2 альтернативы;
- краткое объяснение, почему чай подходит.

### Результат этапа
Появляется интеллектуальная выдача на основе правил, а не просто фильтрация.

---

## Этап 8. Визуальное улучшение интерфейса
### Задача
Сделать интерфейс удобным для реального использования у витрины.

### Что улучшить
- компактные карточки;
- крупные кликабельные элементы;
- читабельная типографика;
- адаптивность для мобильного экрана;
- понятные блоки результатов.

### Результат этапа
Интерфейс выглядит аккуратно и удобен в работе.

---

## Этап 9. Подключение изображений чаев
### Задача
Добавить отображение картинки для каждого чая.

### Рекомендация
Использовать поле `image` в JSON.

### Что должно быть реализовано
- если `image` есть, показывать картинку в карточке;
- если картинки нет, отображать заглушку;
- не ломать интерфейс при отсутствии изображения.

### Результат этапа
Карточки чаев становятся визуально удобнее.

---

## Этап 10. Подключение DeepSeek AI
### Задача
Добавить свободный текстовый ввод с преобразованием в фильтры.

### Что должно быть реализовано
- поле для естественного запроса;
- отдельный сервис `aiService.js`;
- чтение API-ключа из `.env`;
- отправка запроса в DeepSeek;
- получение структурированного JSON-ответа;
- применение результата к существующей системе фильтров.

### Важно
AI не должен напрямую выбирать чай. Он должен только возвращать параметры, понятные приложению.

### Результат этапа
Сотрудник может писать запрос свободным языком, а система превращает его в фильтры и выдает рекомендации.

---

## Этап 11. Fallback-режим без AI
### Задача
Сделать так, чтобы приложение работало и без DeepSeek.

### Что должно быть реализовано
- если нет ключа, AI-блок скрыт или отключен;
- все остальные функции продолжают работать;
- нет падений интерфейса.

### Результат этапа
MVP остается рабочим даже без активного AI API.

---

## Этап 12. Подготовка к деплою
### Задача
Подготовить приложение к публикации по ссылке.

### Что должно быть сделано
- сборка проекта проходит без ошибок;
- проверена работа production build;
- добавлен `README.md`;
- описано, как запускать проект локально;
- описано, как обновлять `teas.json`;
- описано, как подключать `.env` для AI.

### Результат этапа
Приложение готово к выкладке на Vercel или GitHub Pages.

---

## Этап 13. Финальная проверка
### Проверить обязательно
- работает ли поиск по артикулу;
- работает ли поиск по названию;
- работают ли фильтры;
- корректно ли считаются рекомендации;
- отображается ли карточка чая;
- работают ли изображения;
- работает ли AI при наличии ключа;
- не ломается ли приложение без AI;
- удобно ли пользоваться на телефоне.

Если нужно уложиться максимально быстро, обязательный минимум:
- загрузка базы из JSON;
- поиск по артикулу;
- поиск по названию;
- карточка чая;
- фильтры;
- базовая выдача рекомендаций;
- адаптивная верстка;
- деплой.

DeepSeek можно подключить сразу после этого отдельным шагом.
