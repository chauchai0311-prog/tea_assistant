# tea_assistant — Project Overview

## Назначение
`tea_assistant` — это внутренний веб-ассистент для сотрудников чайной точки/магазина. Продукт помогает быстро ориентироваться в ассортименте и подбирать чай под запрос клиента без необходимости каждый раз вспоминать весь материал обучения вручную.

На первом этапе ассистент ориентирован в первую очередь на пуэры, но структура проекта должна позволять расширение на другие категории чая.

## Цель MVP
Собрать быстрый, легкий и удобный внутренний инструмент, который:
- открывается по ссылке на телефоне и компьютере;
- помогает найти чай по артикулу или названию;
- помогает подобрать чай по запросу клиента;
- показывает краткую карточку чая с ключевой информацией;
- выдает рекомендации на основе заранее заданной матрицы соответствия;
- поддерживает AI-ввод только как дополнительную функцию для свободного текстового запроса.

## Формат реализации
MVP реализуется как **web app** на следующем стеке:
- **React + Vite** — интерфейс и клиентская логика;
- **JSON-база** — хранение данных о чаях;
- **логика на матрице соответствия** — основа рекомендаций;
- **DeepSeek API** — только для преобразования свободного текста в структуру фильтров;
- **деплой по ссылке** — Vercel или GitHub Pages.

## Что НЕ входит в MVP
В первую версию не входят:
- нативное мобильное приложение;
- сложный backend;
- база данных;
- авторизация;
- роли пользователей;
- история действий сотрудников;
- аналитика;
- интеграции со складом, CRM и кассовыми системами;
- AI как самостоятельный источник рекомендаций без правил.

## Основные сценарии использования

### 1. Поиск по артикулу или названию
Сотрудник вводит артикул или название и быстро получает карточку конкретного чая.

### 2. Подбор по параметрам
Сотрудник выбирает фильтры, например:
- плотный;
- без землистости;
- новичок;
- термос.

Система возвращает:
- лучший вариант;
- 1–2 альтернативы;
- краткое объяснение выбора.

### 3. Свободный ввод через AI
Сотрудник пишет естественным языком, например:
> Клиент хочет плотный чай без землистости, для термоса, новичку.

DeepSeek преобразует запрос в структурированные параметры. Далее рекомендации строятся не моделью, а по внутренней логике матрицы и тегов.

### 4. Быстрое освежение знаний
Сотрудник открывает карточку чая у витрины и быстро вспоминает:
- профиль;
- вкус и аромат;
- эффект;
- как заваривать;
- для кого подходит;
- какие есть альтернативы.

## Принцип работы рекомендаций
Рекомендательный механизм строится на следующих слоях:
1. данные из JSON-базы;
2. теги и антитеги;
3. матрица соответствия клиентских запросов;
4. score / ранжирование вариантов;
5. выдача основного варианта и альтернатив.

AI не принимает решение о рекомендации самостоятельно. Его задача — только преобразовать свободный текст в нормализованные параметры.

## Требования к интерфейсу
Интерфейс должен быть:
- быстрым;
- простым;
- адаптивным под телефон;
- понятным для сотрудника без технической подготовки;
- пригодным для использования прямо у витрины;
- без перегруженных экранов.

## Экранная структура MVP
Предпочтительный формат — **одностраничное приложение** с основными блоками:
1. Header
2. Поиск по артикулу / названию
3. Быстрые фильтры / теги
4. Поле свободного AI-ввода
5. Блок рекомендаций
6. Карточка выбранного чая
7. Список всех чаев / результатов

## Основные сущности проекта
В MVP используются следующие сущности:
- **Tea** — карточка конкретного чая;
- **Tag** — ключевой вкусовой или функциональный признак;
- **AntiTag** — нежелательный признак;
- **ClientRequest** — набор условий клиента;
- **RecommendationRule** — правило матрицы;
- **RecommendationResult** — список подходящих чаев с приоритетом.

## Данные, которые должны поддерживаться
Для каждого чая в системе должны поддерживаться как минимум:
- артикул;
- название;
- тип/категория;
- класс;
- описание;
- вкус;
- аромат;
- эффект;
- время употребления;
- способы заваривания;
- ключевые теги;
- антитеги;
- подходит ли новичку;
- подходит ли для термоса;
- подходит ли для проливов;
- альтернативы.

## AI-слой
AI в MVP используется ограниченно.

### Назначение AI:
- принять текстовый запрос сотрудника;
- выделить из него параметры;
- вернуть структурированный JSON-ответ для интерфейса.

### AI не должен:
- сам выбирать чай без учета матрицы;
- генерировать рекомендации, противоречащие базе;
- подменять собой внутреннюю логику правил.

## Технический результат MVP
На выходе первой версии должен получиться продукт, который:
- запускается локально и в проде;
- открывается по ссылке;
- позволяет искать чай по артикулу;
- позволяет фильтровать ассортимент;
- показывает карточку чая;
- дает рекомендации по матрице;
- при наличии ключа поддерживает AI-ввод через DeepSeek.

## Дальнейшее развитие после MVP
В будущем можно расширить проект:
- на другие категории чая;
- на обучение и квизы;
- на админку редактирования данных;
- на подключение базы данных;
- на учет остатков;
- на внутреннюю аналитику;
- на более развитый AI-интерфейс.

Но все это не является частью первой версии.
